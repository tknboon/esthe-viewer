## ✅ このセッションで修正済み (重大 3 件)

### 修正 1: `parseSimpleYaml` の強化 [`app.js:679`]

**問題**
- キー行 `^([A-Za-z0-9_/-]+):\s*$` は末尾スペース・行末コメント不可
- ブロックスカラー (`|` `>`)、フロー記法 (`[...]` `{...}`)、アンカー・エイリアス (`&` `*`) 未対応
- 既存YAMLを取り込むと候補がサイレントに欠落

**対応**
- 未対応構文を検出して行番号付き警告 (最大 5 件アラート、それ以上は「他 N 件」)
- `key: value` インライン記法を `items[0]` として受け入れ
- 認識できない行も警告レポート
- 処理は継続 (壊れた行をスキップして残りは読み込む)

**残タスク**: 完全対応する場合は `js-yaml` を CDN 経由で導入するのが本命。

### 修正 2: HTML5 drag / mouse fallback の二重発火防止 [`app.js:1751-1866`]

**問題**
- `bindYamlBlockReorder` の `mousedown` と `dragstart` が両方 state を書き換える
- ネイティブ drag 発火後の `mouseup` で `endYamlPointerDrag` が動き、既に処理済みの並べ替えを**再度実行**する可能性

**対応**
- `dragstart` 発火時に `pointerDraggedYamlKey = ""` として fallback 無効化
- `dragend` / `drop` でも pointer 状態と mousemove リスナーを確実に解除
- `endYamlPointerDrag` は `pointerDraggedYamlKey` が空なら何もしない
- ネイティブ drag 非対応環境では従来通り fallback が動作

### 修正 3: `render()` 時のカーソルリセット防止 [`app.js:1111`]

**問題**
- `render()` は `keyList.innerHTML = ""` + 各 input の `.value` 上書きで全再構築
- `saveKeyButton` で `render()` が走ると **編集中の `itemTextarea` のカーソル位置がリセット**
- 長文入力後の反映ボタンでカーソルが飛ぶ運用ストレス

**対応**
- `document.activeElement` を確認し、フォーカス中のフィールドは `.value` 上書きしない
- 対象: `keyNameInput` / `keyLabelInput` / `itemTextarea`
- 非フォーカス中でも `itemTextarea` は値差分がある時のみ代入 (セレクション破壊回避)

## 🟡 残タスク: 中程度 7 件

### 中 1: `escapeHtml` の予防的強化 [`app.js:1277`]

現状は `&<>` と `"` のみエスケープ。単引用符 `'` は未対応。
key 名は `normalizeKeyName` で `[a-zA-Z0-9_/-]` に絞られているため現状は安全だが、将来 `'attr'` 属性を使うと即 XSS。
候補行テキストは属性値になるパスがあるため予防的対応推奨。

**推奨パッチ**:
```js
function escapeHtml(value) {
  return String(value)
    .replace(/&/g, "&amp;")
    .replace(/</g, "&lt;")
    .replace(/>/g, "&gt;")
    .replace(/"/g, "&quot;")
    .replace(/'/g, "&#39;");
}
```

### 中 2: `state` の並列辞書構造 [`app.js:86-97`]

```js
state = { data, labels, disabledKeys, sequentialKeys }
```
4 つの並列 map を key ベースで手動同期。`saveKeyButton` (line 1584) が旧キーから新キーに 4 つ全部を移す必要があり、追加・削除・複製・rename の各所で**同期漏れリスク**が高い。

**推奨リファクタ**:
```js
state.data[key] = {
  items: string[],
  label: string,
  paused: boolean,
  sequential: boolean
}
```
`loadState` で旧 → 新 の migration を書けば後方互換維持。

### 中 3: SEQ トグル時のフィードバック不足 [`app.js:1697` `bindSeqToggleOutput`]

- 参照 1 箇所をクリック → そのキー**全参照**が SEQ 化される
- UI 上はこの範囲が読み取れない

**推奨**: トグル時に「このキーへの参照 N 箇所が SEQ 化されます」トースト。

### 中 4: `renderKeyNameSuggestions` の遅延化 [`app.js:473`]

`state.data` と seeds を毎回全走査。キー数が数十以上でサジェスト計算が重くなる。
`render()` からも呼ばれるので毎再描画で発火。

**推奨**: フォーカス時のみ計算、`state.data` 変更時のみメモ再構築。

### 中 5: `keyNameSuggestionSeeds` と `labelRules` の日本語化

- 現状: `["delivery_cast_hair_color", "Hair Color", "Hair / Face"]` のように英字ラベル
- 「非エンジニア向け」を掲げるなら **`"髪色"`, `"髪 / 顔"`** 等に統一

### 中 6: `patternCountSummary` の Notes 表記英語 [`app.js:819`]

`"Cycle: ..."` / `"Undefined: ..."` / `"Root keys"` / `"Prompt total"` が日本語UIに混在。
統一を推奨。

### 中 7: 部品棚 import の重複警告 [`app.js:1663`]

```js
keyLibrary = { ...keyLibrary, ...imported };
```
上書きされた key が UI に出ない。「既存の X 件を上書き」の情報を出す。

## 🟢 残タスク: 軽微 6 件

### 軽 1: `labelRules` の regex 順序依存性
配列位置で優先順を決めており、追加時に意図しない一致リスク。
コメントで「変更時は上位ルールを確認」の注意書き推奨。

### 軽 2: `normalizeKeyName` のハイフン → アンダースコア変換
`hair-color` のような命名で書きたいユーザーがハマる。挙動をコメントで明記。

### 軽 3: `unquoteYamlScalar` のエスケープ
`JSON.parse` を double quote で使う実装。`\n` `\t` の扱いが YAML 仕様と微妙に違う。多くは無害。

### 軽 4: `download` のUTF-8 BOM 
Windows メモ帳で開くと文字化けする可能性。BOM 付き選択オプション追加が親切。

### 軽 5: `library-actions` のボタンラベル英字
`Add` / `Overwrite` / `Delete` を `追加` / `上書き` / `削除` に。

### 軽 6: YAML/JSON import の拡張子誤選択リスク
ドラッグ&ドロップで拡張子判定して自動振り分けすると事故が減る。
